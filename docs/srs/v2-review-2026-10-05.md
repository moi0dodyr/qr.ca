# SRS v2.0 review: where we stopped (2026-10-05)

The BA published **SRS v2.0** and **Product Backlog v2** in Notion on 2026-10-05 (internal draft for review). **Adopted on 2026-10-06:** v2.0 is the source of truth ([0005](../decisions/0005-adopt-srs-v2.md)); the copy is in [`upstream/v2.0_2026-10-05/`](./upstream/v2.0_2026-10-05/).

## What was read

Everything: the SRS main page, section 10, sections 11–16, Appendix A, the Backlog index, all 30 feature pages (with traceability blocks) and the 93-row "all stories" table. The only thing not re-read is the SRS v1.0 link, which is already in `upstream/`.

## What v2 is

The BA's note says it has the same scope and decisions as v1.0, reorganised by role (User, Admin, QR.CA business, System) and by the order people meet the product, with plainer text. The acceptance criteria now live only on the Backlog feature pages. Every v1 ID (QR-U-01…44, QR-A-01…06) is still in each story's traceability block, so our QR-U references keep working.

## Effect on the audit ([open items](../design/figma-audit-open-items.md))

- **FD-06** needs rewriting: draw a time-based redirect **type** (step 1 → periods in step 2), not Schedule settings. Rules unchanged: default link, time zone, overlap error, pause beats schedule.
- **FD-01** target list per v2. Dynamic: Website, PDF / File, Multi-link page, vCard, App store link, Menu, Review, Time-based redirect. Static: Website, Contact (vCard), Email, SMS, Phone call, Plain text, Wi-Fi. No static Links Page, so the static *Linkpage* `8256:11635` in Figma isn't in v2.
- **#83** is now decided by v2: static codes edit name, folder and tags only. Still parked for the design stage.
- **#59, #86, #51** are v2 acceptance criteria. Parking them is fine, but they must be built.
- **#84, #27, FD-07, FD-09, #68, #71** are still required. v2 lists folder rename and delete, GA4 / Meta Pixel and the Google-password case as open design questions.
- **#26, #49, #50, #62, #87** match v2.

## Oleg's answers (2026-10-06)

1. **Contact vs vCard:** merge, as v2 says. [0006](../decisions/0006-static-contact-is-vcard.md) supersedes 0003; DR-04 withdrawn.
2. **Time-based redirect as its own type:** yes, Oleg's call. FD-01 and FD-06 rewritten. Removing the type from V1 is to be discussed on 2026-10-06; FD-06 is on hold until then.
3. **Adopt v2.0:** yes, it's the new source of truth ([0005](../decisions/0005-adopt-srs-v2.md)).
4. **Archive Download:** follow v2's Archive story (Download locked in the Archive without a plan). Figma changes: audit #102.
5. **Name at sign-up:** audit #105 is on hold until a talk with the BA. v2 removes Name from sign-up (QR-U-03) but never asks for it anywhere else: it's only editable in Account Settings (QR-U-36), and *Delete account* makes the user type their full name (QR-U-37). **Question for the BA:** how do we get the user's name if onboarding doesn't ask for it? Possible answers: keep Name at sign-up, ask for it in the Welcome step, or take it from Google and leave it empty for email sign-ups (then *Delete account* needs another confirmation, e.g. typing the email).

DR table updated: DR-02 and DR-04 withdrawn; DR-01 and DR-05 carry the v2 wording and stay to send.
